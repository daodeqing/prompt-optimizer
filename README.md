# 提示词优化器 1.3.0

选择项目，输入原话，获得可复制的提示词。最低 Cindy 0.1.125；插件由 Cindy 独立运行，不依赖本次编程会话，也不要求安装 Python、npm 或外部 PDF 工具。

## 使用

1. 打开插件工作台，点击“选择项目”。
2. 首次选择并保存优化模型，之后聊天与工作台始终沿用这个来源和型号。
3. 输入原始提示词，点击“优化提示词”，完成后点击“复制”。

任务类型默认自动识别，也可手选工程、编程、论文/研究、写作、分析。详细程度默认按需要判断，也可选精简、标准、详细。简单清晰的请求允许基本保留，必要信息不足时只补少量占位或条件要求。只生成提示词，不执行原任务。

聊天调用默认把完整成品只放在结果卡中，工具回执只保留交付状态与资料元数据，避免同一提示词出现两份。只有用户明确看不到卡片时，才用同一个 request_id 查询并选择文字交付。

## 降智测试

工作台和 candy_test 工具会用已保存模型回答参考仓库中的糖果题，默认运行 3 次，最多 5 次。每次都是独立的闭卷任务，模型必须返回 final_answer 和 reason；插件按最终 final_answer 是否为 21 评分，逐次显示通过、未通过、无法评分或请求失败，并保留模型、来源、推理强度和耗时。

测试不读取项目资料，也不执行用户任务。21 依赖原题中的“不同形状靠手感可以分辨”前提。账号权限、模型波动、系统上下文和供应商路由都会影响结果；单题错误或一次低通过率不能单独证明账号被降智。

## 项目资料、PDF 与会话

自动只读筛选所选目录内的文本、代码、方案和文字型 PDF，无需手填文件路径。PDF 使用随包的 Mozilla PDF.js 本地提取文字，支持中文、多页与页码引用。文字片段在本地排序后才进入模型上下文；明确要求参考 PDF 时为相关 PDF 页面保留位置。

PDF 支持的是文字层提取，不包含 OCR：扫描件/无文字页面会提示需要 OCR；加密 PDF 提示先解锁，损坏文件明确提示解析失败。每个 PDF 上限 12 MiB、80 页、220000 字符；一次最多解析 12 份、总输入不超过 32 MiB。超限会显示截取或未读状态。PDF 不执行文档脚本、不追踪外部链接，也不联网下载字体。

项目会话由已保存模型在同一次优化任务中，通过 Cindy 内置 cindy_helper 的 search_chat_history/get_chat_history 查询，必须限定所选项目的 workdir、本机与用户/助手记录；不直接读取宿主数据库。插件核对同目录的真实工具调用与成功回执，未取得回执不会把模型自报当作读取成功。界面分别显示已读取、查询成功但没有具体引用、无结果和不可用。宿主不可用或用户拒绝时，保留已读项目资料并明确提示会话未读。会话范围跟随 Cindy 的目录过滤规则，按相关性读取，不把全部历史全文塞进模型。

未保存项目时，聊天调用使用宿主注入的当前本机目录；已保存项目优先。远程目录不会作为本机路径读取。隐藏目录、依赖、构建产物、常见凭据文件及项目外符号链接默认排除。普通 Office 文件和扫描图片暂不自动解析。

## Token 与恢复

本地扫描最多查看 6000 个目录项、检查 200 个候选、成功读取 100 份资料或约 2 MB 文本，再返回最多 36000 字符候选片段。进入模型的预算按任务收缩，简单任务默认约 4500 字符，精简约 3500，复杂自动约 12000，详细约 18000，另受宿主输入总长度限制。预算是字符预算，不等于精确 Token 数。

会话工具查询会增加模型回合；Cindy 普通任务本身带有系统上下文。实际 Token、缓存与费用以供应商账单为准，不承诺固定节省比例，也没有硬性输出 Token 上限。已保存模型不可用时停止，不静默换型号。

每次请求保存稳定编号、模型和资料快照。超时或状态未知时点击“继续查看”，聊天调用 query_optimization 查询原编号，不通过换编号重发。无效模型输出不会自动重复计费调用。取消不保证返还已经产生的费用。结果状态在正文外展示，复制按钮只复制成品。
